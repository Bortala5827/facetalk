# FaceTalk v2.0 功能说明：30 秒试音互评

> 状态：**代码已完成，规划上线中**（需 D1 建表 + 部署后开启）。当前线上版本为 **v1.0**（双向匹配 + 文字留言）。

## 一句话定位
匹配成功后、决定组队前，双方先各录一段 **30–60 秒**的试音互听互评；**双方都愿意**才解锁留言板与联机信息，任一方婉拒则房间 **60 秒自动解散**——把"聊了半小时才发现不合适"的精力浪费挡在组队之前。

## 解决的痛点
v1.0 只做文字匹配，双方进了房间才发现语气/表达/默契不对板，浪费时间。v2.0 用一段短录音做"低成本的面对面预筛"。

## 核心流程（强制前置门控）
1. 匹配成功 → 进入 **试音环节**（不解锁留言板/联机信息）。
2. 系统**随机出题**（20 道面试题按房间 ID 确定性哈希，双方同题，零存储）。
3. 各自录 **30–60 秒**试音 → 分片上传。
4. 互听对方录音，从**清晰度 / 逻辑 / 节奏**三维评分，并选择「愿意组队 / 婉拒」。
5. 结果：
   - 双方都「愿意」→ 试音通过，解锁留言板 + 联机信息。
   - 任一方「婉拒」→ 房间进入 **60 秒解散倒计时**，到点自动关闭。

## 关键规则
- **严格时长**：低于 30 秒禁止提交（提示重录），达到 60 秒自动停止；非 30–60 秒的录音服务端直接丢弃。
- **系统随机出题**：题目由 `pairId` 用 FNV-1a 哈希映射到 20 道题之一，双方看到同一题，无需在云端存题。
- **分片上传**：录音在浏览器端用 `MediaRecorder` 采集，转 base64 后按 48KB 分片循环上传，规避 D1 单值大小限制。
- **内存播放、本地不落盘**：播放用 `URL.createObjectURL(new Blob(...))` 在内存中生成，离开页面即 `revokeObjectURL` 销毁，不写 `localStorage` / `IndexedDB`。
- **阅后即焚**：一方提交评价后，服务端立即物理删除**对方**的录音（音频分片 + 记录一并清除）；兜底：超过 2 小时无人评价则定时清理强删。
- **降级兼容**：若 D1 未建 `voice_clips` 等表，`/api/voice` 返回 `gate:'skip'`，前端整段跳过试音，老房间与留言板零影响。

## 隐私承诺
录音**仅在会话期间存在于云端缓存**，评价完成或超时后**自动删除**；**云空间与本地设备均不长期储存**任何录音文件。
